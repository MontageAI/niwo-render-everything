# content.json 字段协议

素材包根目录下的 `content.json` 声明这条片子的**内容**。这份 JSON **不接受任何未列出的字段**，多写一个键会直接校验失败。

成片形态、音色、语速、字幕开关、IP 形象、背景音乐、渲染模型和输出路径都**不在**这份协议里——那些是用户在 Niwo 里渲染前自己选的，选完由 Niwo 写进素材包的 `render.json`。你既没有判断依据，写了也只会被忽略。你只负责内容。

## 模板

```json
{
  "schema_version": 1,
  "title": "DeepSeek API 涨价",
  "script": "把定稿的口播文案放这里，一整段，不要换行符",
  "hook_headline": {
    "lines": ["投248亿", "账面[[多出一万亿]]"]
  },
  "sources": ["宇树科技招股书", "DeepSeek 官方公告", "新浪财经"],
  "pronunciations": {
    "调用量": "diao4 - -"
  },
  "notes": "可选，留给用户的说明"
}
```

只有 `schema_version`、`title` 和 `script` 是无条件必填，其余可以省略。两处例外：

- `hook_headline` 是有条件必填：用户要的成片形态是竖屏信息版时必须写，另两种形态必须省略，见下面的字段说明。
- `sources` 协议上可省，但**只要文案引用过公开资料就默认写上**，不用问用户要不要带；显示与否是用户在渲染界面上的开关。

## 字段说明

### schema_version

固定 `1`。

### title

给这条片子起个标题，用户在 Niwo 里靠它认出这个素材包。中文即可，上限 120 字，不要换行。

### script

**必填。** 定稿口播正文，一整段不换行，上限 6000 字。

它会被逐字朗读成配音、逐字显示成字幕，Niwo 不会改写、润色或增删一个字。所以里面不能有标题、分段小标、镜头说明、emoji 或者括号里的舞台提示，只能是能直接朗读的成品正文。

### hook_headline

**只有竖屏信息版会渲染它，也只有竖屏信息版必须写它。** 竖屏信息版在嵌入式横屏内容上方有一条专用标题带，放的就是这个**钩子大标题**（Hook Headline），用来在开场几秒内抓住注意力。它不进配音、不进字幕，与 `script` 完全独立——`script` 是口播正文，这里是视觉包装用的短标题。

跟形态的绑定是双向的，两边都不能将就：

- 用户要竖屏信息版却少了这个字段：标题带没有内容，成片顶部会空掉整块版面，Niwo 不会拿 `title` 或 `script` 去补。而且形态初值会退回竖屏视频，用户在界面上改回信息版之后看到的就是那块空白。
- 用户要竖屏视频或横屏视频却写了这个字段：这两种形态没有这块版面，标题不会出现在画面上，同时 Niwo 会把渲染界面的形态初值设成竖屏信息版，跟用户选的形态冲突。

标题内容要跟口播文案一起给用户确认过再写进来，别自己拍板。

```json
"hook_headline": {
  "lines": ["投248亿", "账面[[多出一万亿]]"]
}
```

**结构**

- `lines`：1 到 3 行字符串，推荐 2 行。第一行铺垫，第二行给结果或冲突。
- 行内用 `[[...]]` 标记需要高亮色块强调的关键词。一行最多 2 处，整条标题至少 1 处。

**写法规则**

- 每行长度按去掉 `[[` `]]` 后的**可见宽度**算，单位是一个中文字：中文、日文、韩文和全角标点各算 1 个，英文字母、数字、半角标点各算 0.56 个。超过 12 会告警，超过 14 会校验失败（标题带放不下）。所以 `DeepSeek砸1.4亿` 虽然有 13 个字符，只折合 8.2，很宽裕。
- 行内不能有换行符。标记必须成对、不可嵌套、高亮内容不能为空。不支持字面量 `[[` 或 `]]`。
- 只写短标题，不要写成完整口播句。用户要的不是竖屏信息版时一律省略此字段。

**好例子**

```json
"hook_headline": {
  "lines": ["DeepSeek砸1.4亿", "一锁就是[[36个月]]"]
}
```

```json
"hook_headline": {
  "lines": ["投248亿", "账面[[多出一万亿]]"]
}
```

**坏例子**

```json
"hook_headline": {
  "lines": ["[[DeepSeek掏出1.4个亿战略投资宇树科技]]"]
}
```

整行全高亮，没有铺垫与强调的层次。

```json
"hook_headline": {
  "lines": ["家人们杭州科技圈今天炸出个大瓜DeepSeek掏出"]
}
```

一行折合 21.5 个字宽，远超标题带容量；且写成了口播正文而非标题。

```json
"hook_headline": {
  "lines": ["投248亿", "账面多出一万亿"]
}
```

没有任何 `[[ ]]` 高亮，退化成普通标题，校验会通过但会告警。

### pronunciations

多音字读音。文案定稿后扫一遍，把配音容易读错的字写进来。比如「调用量」的「调」该读 diào，配音默认会读成 tiáo：

```json
"pronunciations": {
  "调用量": "diao4 - -",
  "重要": "zhong4 -"
}
```

键是文案里出现的词，值是与它**逐字对应**、空格分隔的拼音，带声调数字（1 到 4 声，轻声用 5），`ü` 写作 `v`。`-` 表示这个字不用管，交给配音自己判断。

规则：

- 音节数必须和词的字数完全一致，`调用量` 三个字就要三个音节。
- 一个词条不能全是 `-`，那说明没有需要修正的读音，应该整条删掉。
- 每个词只需写一次，文中所有出现的位置都会生效。
- 只标真正会读错的那个字。标得越少配音的语气越自然，字幕时间戳也越准，所以别整句都注音。

这些标注只影响配音，`script` 和字幕保持原样。

### sources

资料来源名称列表，渲染为画面底部的小字。**默认都写上，不用问用户要不要写**：写文案时查过哪些资料只有你清楚，而要不要露在画面上是用户在 Niwo 渲染界面上的开关。文案确实没引用任何公开资料时才省略这个字段。

```json
"sources": ["宇树科技招股书", "DeepSeek 官方公告", "新浪财经"]
```

规则：

- 每条不超过 24 个中文字宽（英文与数字按半个字算）。条数不限，但写得越多底部小字就多占几行。
- 只写来源名称，如公告名、媒体报道名、招股书等，不要写 URL。
- 只写来源名，「资料来源：」前缀和多条之间的分隔符由 Niwo 拼。
- 省略或空数组时底部不显示来源小字；用户在渲染界面上关掉来源开关时同样不显示，`content.json` 不受影响。
- 免责声明是另一回事：它有自己的开关，正文也由用户在渲染参数里显式填写，跟 `sources` 互不牵连——只写来源不出免责声明，只出免责声明不写来源，都是允许的。

### notes

可选，留给用户的补充说明，上限 2000 字。比如某个素材为什么没找到、哪一段建议用户自己补图。

## 不要写这些

以下字段都由用户在 Niwo 里渲染前决定，Niwo 会把它们写进素材包的 `render.json`。写进 `content.json` 会因为「未知字段」直接校验失败：

- 成片形态 `video_format`（旧写法 `aspect_ratio`）：横屏、竖屏还是竖屏信息版，由用户在界面上选。你只按第零步确认的取向收素材，并在 `notes` 里提醒用户选一致的形态
- 音色 `voice_id`、语速 `speed`
- 字幕开关、章节进度条开关、IP 形象开关与活跃度
- 成片明暗基调 `theme`：整片是浅底还是深底由用户在界面上选，具体配色由分镜模型定
- BGM 情绪、具体曲目、音量
- 智能音效的编排档位与音量倍率
- 渲染模型、模板、各种 `enable_*` 开关
- 输出路径、`task_id`、`user_id`
- 免责声明的开关与正文，以及来源小字要不要显示：都由用户在渲染界面上决定

你的交付物里不需要、也不应该包含 `render.json`。
